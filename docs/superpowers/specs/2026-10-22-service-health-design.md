# 服务持续健康检查

在本地服务网络上增加可选的持续健康检查，默认关闭。进程启用检查后，必须在启动期限内为自己的目录会话登记 HealthProbe，满足服务登记条件后进入 Ready。原子替换现存端点保留连续登记的起始时间，断开后重新登记则重新计时。Check 返回业务健康状态；默认示例检查 SDK 调度序列能否响应。

监管器由宿主 poll 驱动，无额外计时线程。每个探测端点最多保留一个底层请求；超时不会无限增加传输回调。响应记录实际接收时间，宿主晚轮询不影响期限判定。替换探测端点不会清空连续失败次数或延长当前检查期限，旧端点的迟到响应不参与新结果。

连续失败达到阈值后关闭进程会话，等待配置的退出宽限期，再强制终止并回收。恢复使用已有有限重启预算和退避，不重放业务请求。订阅者观察旧服务移除和新代次加入。失败、主动停止和新一轮启动均释放旧检查状态。

控制协议追加 HealthProbe 和 Directory.SetHealthProbe，保留既有方法序号，不改变 native ABI。端点只属于登记它的受信会话，注销及端点析构发生在全局目录锁外。

验证包括纯状态机的时间边界、端点替换、连续失败恢复和容量约束，以及真实多进程健康、无响应、重启耗尽、启动缺少探测端点、订阅重连与退出回收。
